## 编号、状态与评估规则

- ID 永久稳定，不重编号、不复用。当前最高编号 SL-023，下一条新需求用 SL-024；同类新反馈合并到原项。取消或放弃时保留条目、日期和原因。子任务使用原 ID 加后缀（如 SL-004-A），不占用新需求编号。
- 编号澄清（2026-10-15，用户已确认）：最新反馈中称为「SL-010 单条任务删除入口优化」的事项，正式登记为 **SL-019**；原 SL-010「自定义主题配色」保持不变，后续引用删除入口时使用 SL-019。
- 类型使用 Bug / UX / Feature / Visual / Technical。工作量使用小 / 中 / 大 / 待评估，仅为相对估算，不换算成精确工时。
- 状态变化需记录日期、理由和证据；进入 Planned / In Progress 须有明确开发请求。当前没有因本次登记而自动开工的需求。
- Done 要求验收标准满足且用户确认，发布与 Done 分开。实现 Commit、测试记录、用户确认日期、发布版本/链接分别填写；没有正式发布时不填已发布版本。

## 近期与核心需求

### SL-001

**专注模式阅读与编辑分离**

- 类型：UX；来源：用户实际体验及第一轮 UX 开发请求。
- 当前问题：原来阅读和表单混在一起，长表单挤占清单，保存按钮不易找到，保存后未收起。首轮已改为折叠、只读、独立抽屉并提交，但不能把未最终验收的改进记为 Done。
- 目标体验：默认紧凑；点击标题阅读，点击编辑进入面板；长内容舒适，保存栏始终可见，保存成功关闭面板并回到紧凑清单，草稿受保护。
- 推荐实现方向：复用当前 TaskReader / TaskEditor 和串行持久化保护，针对验收反馈小范围修正，不重新设计数据库。
- 优先级：P0；预计工作量：中（主体已实现并提交，剩余验收修正按反馈评估）；技术风险：中，涉及草稿、异步写入、焦点及窄屏回归。
- 前置依赖：既有任务持久化已存在；不依赖驻留模式。需要用户确认：最终阅读/编辑流程及所有边界是否满足。
- 当前状态：In Review。首轮开发提交保留；UX2.2 回归通过 TypeScript、Lint、88 项前端、11 项 Rust 和 20 组原生桌面检查，完整编辑抽屉及草稿保护不变；用户认可大部分首轮改进，但尚无本项完整验收；未发布。
- 验收标准：默认紧凑行；标题点击只读且保留换行；编辑为同窗口独立抽屉；2000 字以上计划可编辑、保存并重新完整读取；宽窄窗口滚动不遮挡保存；成功持久化后收起；失败保留输入且无成功提示；取消、Esc、关闭及任务/日期/模式切换不静默丢稿；勾选独立、已有数据完整；用户确认通过。
- 相关 Commit / PR / Issue：首轮实现 [`23a7cd3`](https://github.com/YOLIIIIII/starry-list/commit/23a7cd3941a28d0724e254ca7b9bb71c9b8fd5c8)（含使用手册、截图与验证记录）；PR / Issue 未创建。初始基线 `830b88f` 不包含本轮 UX。

### SL-002

**七天日程空状态优化与快速新增收起**

- 类型：UX；来源：用户实际体验、第一轮 UX 请求及本次追加反馈（2026-10-15）。这是同一需求的补充，不另立重复 ID。
- 当前问题：用户安装 UX2 后认可空输入收起和数据保护，但认为非空快速新增的三选一切换提示繁琐。UX2.1 主动导航自动新增后，用户仍反馈普通空白及切换 Windows 应用只失焦不保存。UX2.2 增加应用内和原生窗口失焦自动新增，显式取消仍确认；等待最终验收。
- 目标体验：真实任务最醒目，空日期只保留日期、数量和加号；快捷新增出现与消失自然，同时保护已输入但未保存的标题。
- 推荐实现方向：保留单一受控 quickDraft，QuickAdd 通过同一 save 方法处理 Enter、添加按钮、区域失焦、窗口失焦和导航保存；共享进行中的 Promise，guard 等待持久化成功后执行原操作，失败不导航。取消意图优先于失焦；IME 失焦延后至 compositionend 后读取最终值，组合期间不提交或切换。已有任务编辑器的确认保持独立。
- 优先级：P0；预计工作量：小（追加 UX 修复）；技术风险：中，重点是失焦事件顺序、输入法、异步保存和非空草稿丢失。
- 前置依赖：复用原 store.add / SQLite，数据库结构不变。需要用户确认：自动新增是否自然，取消、失败与快速切换是否符合预期。
- 当前状态：In Review（UX2.2）；用户认可此前空白收起和数据安全；本轮增加可靠失焦提交及新增撤销，实际测试与构建证据见验证记录，仍待最终用户验收，未正式发布。
- 验收标准：
  1. 点击日期「+」后展开对应输入框并自动获得焦点。
  2. 输入框为空或只有空白时，点击输入区域之外的位置自动收起；区域内点击或点提交按钮不能误触发取消。
  3. 空输入时，再点对应「+」可以收起。
  4. 空白按 Esc 直接收起；非空按 Esc、点击关闭或再次点当前日期加号时，先确认「继续填写 / 放弃草稿」，不得直接丢弃；IME 组合阶段不误取消。
  5. 输入标题按 Enter，只有持久化成功后收起并显示真实任务；失败保留输入及错误。
  6. 非空标题主动切换日期、视图、七天范围或其他日期新增入口时，自动添加到原目标日期，等待成功后再执行原操作，不出现三选一导航提示；失败保留原草稿并阻止切换。普通空白点击、离开输入区域及 Windows 窗口失焦也尝试保存，成功才清稿；失败保留原日期、输入、错误和重试入口。
  7. 同一时间最多展开一个新增区；提交或自动新增期间禁用重复提交，多次 Enter / 导航点击不产生重复任务；IME 组合阶段不能误导航。
  8. 切换日期范围或视图，不留下失效空输入框；返回时不复活已失效的空输入。非空草稿仍遵守第 6 项。
  9. 不影响正常新增、编辑、完成、日期归属、优先级和数据库保存；原有数据完整。
  10. 失焦自动新增成功显示「已添加任务 · 撤销」，撤销真正移除新任务；内部点击不误提交，显式取消不被 blur 抢先；多个来源共享同一保存 Promise，不重复 INSERT。退出失败、强制结束或尚未持久化不能伪称成功。
  11. 空日期无重复占位提示，整段为空最多一个整体提示，真实任务层级高于新增提示；用户体验确认后才关闭本需求。
- 相关 Commit / PR / Issue：UX2.2 实现 [`afd262f`](https://github.com/YOLIIIIII/starry-list/commit/afd262f6923828097b7ccb7bf39eb51680aa9da0)；UX2.1 实现提交：[`6d7c64e`](https://github.com/YOLIIIIII/starry-list/commit/6d7c64e5127d600a7e61485d9f44faa42e89bdd1)；UX2 历史提交 242fad5 保留；PR / Issue 未创建。

### SL-003

**透明窗口视觉体系重设计**

- 类型：Visual；来源：用户实际体验。
- 当前问题：矩形顶栏与外层圆角不协调，阅读层次不足，复杂壁纸穿透干扰内容，专注背景块不统一。
- 目标体验：统一圆角玻璃底板，顶部与主体协调，少量背景层和舒适内边距，透明与不透明状态都清晰。
- 推荐实现方向：先盘点背景 alpha、圆角裁切与衬底，再评审局部视觉方案；不顺带改驻留机制。
- 优先级：P1；预计工作量：中；技术风险：中高，WebView2、GPU、透明窗口裁切与对比度差异。
- 前置依赖：现有透明/不透明回退；与 SL-004 协调视觉层级，但不硬性串行。需要用户确认：复杂背景与实色方案的观感。
- 当前状态：Backlog；尚未开发、测试或验收；未发布。
- 验收标准：顶栏与外层圆角无突兀矩形；明暗、复杂测试背景下标题和任务可读；40%–100% 设置语义不变；文字/输入控件不整体变淡；减少背景层不损害滚动与宽窄布局；不透明回退正常；使用合成测试背景，不公开私人壁纸。

### SL-004

**默认字号和全局字号设置**

- 类型：Feature；来源：用户实际体验与设计讨论。
- 当前问题：原 11px / 13px 不协调，UX2 统一 15px 后用户认为相对整体略大。UX2.1 将两视图输入、占位符和真实任务标题统一为 14px；整体字号档位仍未开发。
- 目标体验：局部正文与快速新增保持协调，以 UX2.1 的 14px 为当前基准，清晰度优于原 11px；不缩放整页，不顺带改变月历、顶部或编辑抽屉。全局字体层级及小 / 标准 / 大档位另行评审。
- 推荐实现方向：局部子任务已实现，暂不新增设置项或数据字段。后续与 SL-003 评审正文、日期及辅助字体层级，再独立实现全局档位与持久化，不能以本轮局部调整代替。
- 优先级：P1；预计工作量：中；技术风险：中，窄屏、DPI、长标题、表单和计数重叠。
- 前置依赖：SL-004-A 不依赖 SL-003 或全局字号设置，可与 SL-002 / SL-019 一轮处理；全局层级与 SL-003 共同评审可读性。需要用户确认：局部文字协调程度、默认层级及三个档位实际观感。
- 当前状态：Backlog（父需求保持未完成）；仅 SL-004-A 已实现并待用户验收，全局字号设置未开发、未验证或发布。
- 验收标准：
  1. 两种视图的快速新增输入文字与已有任务标题字号基本一致；UX2.1 任务正文以约 14px 为当前设计基准，实际层级需经用户体验确认。
  2. 占位符可降低颜色强调，字号与输入文字保持一致，不通过缩小占位符制造层级。
  3. 380px 窄窗口、宽窗口及不同 DPI 下，无水平溢出、按钮裁切、重叠；长输入仍可编辑，Enter / Esc / 中文输入及失败保留行为不变。
  4. 全局范围：默认任务和辅助文字比现状易读；设置提供字号档位并重启保留，各档长标题合理换行/省略且完整内容可访问；窗口尺寸与任务日期不受影响。
  5. SL-004-A 通过仅表示局部字号修复验收，不表示全局设置完成，父需求不能因此直接标 Done。
- 子任务 **SL-004-A：快速新增输入框字号协调**。优先级 P1；工作量小；风险低至中；状态 **In Review**（UX2.1 实现，UX2.2 保持并回归）。用户认可改善可读性，但认为 UX2 的 15px 过大；本轮统一为 14px。宽窄窗口、长中文与缩放验证见验证记录；不整体 zoom，不开发全局字号设置，仍待用户确认。
