## 编号、状态与评估规则

- ID 永久稳定，不重编号、不复用。当前最高编号 SL-019，下一条新需求用 SL-020；同类新反馈合并到原项。取消或放弃时保留条目、日期和原因。子任务使用原 ID 加后缀（如 SL-004-A），不占用新需求编号。
- 编号澄清（2026-10-15，用户已确认）：最新反馈中称为「SL-010 单条任务删除入口优化」的事项，正式登记为 **SL-019**；原 SL-010「自定义主题配色」保持不变，后续引用删除入口时使用 SL-019。
- 类型使用 Bug / UX / Feature / Visual / Technical。工作量使用小 / 中 / 大 / 待评估，仅为相对估算，不换算成精确工时。
- 状态变化需记录日期、理由和证据；进入 Planned / In Progress 须有明确开发请求。当前没有因本次登记而自动开工的需求。
- Done 要求验收标准满足且用户确认，发布与 Done 分开。实现 Commit、测试记录、用户确认日期、发布版本/链接分别填写；没有正式发布时不填已发布版本。

## 近期与核心需求

### SL-001

**专注模式阅读与编辑分离**

- 类型：UX；来源：用户实际体验及第一轮 UX 开发请求。
- 当前问题：原来阅读和表单混在一起，长表单挤占清单，保存按钮不易找到，保存后未收起。首轮已改为折叠、只读、独立抽屉并提交，但不能把未最终验收的改进记为 Done。
- 目标体验：默认紧凑；点击标题阅读，点击编辑进入面板；长内容舒适，保存栏始终可见，保存成功关闭面板并回到紧凑清单，草稿受保护。
- 推荐实现方向：复用当前 TaskReader / TaskEditor 和串行持久化保护，针对验收反馈小范围修正，不重新设计数据库。
- 优先级：P0；预计工作量：中（主体已实现并提交，剩余验收修正按反馈评估）；技术风险：中，涉及草稿、异步写入、焦点及窄屏回归。
- 前置依赖：既有任务持久化已存在；不依赖驻留模式。需要用户确认：最终阅读/编辑流程及所有边界是否满足。
- 当前状态：In Review。开发：首轮已提交；自动化：本次复跑 TypeScript、Lint 和 59 项前端测试通过，既有记录 11 项 Rust；桌面：既有记录 12 组 Windows 11 测试，本次未重跑；用户：大部分首轮改进获认可，尚无本项完整验收；发布：未发布。
- 验收标准：默认紧凑行；标题点击只读且保留换行；编辑为同窗口独立抽屉；2000 字以上计划可编辑、保存并重新完整读取；宽窄窗口滚动不遮挡保存；成功持久化后收起；失败保留输入且无成功提示；取消、Esc、关闭及任务/日期/模式切换不静默丢稿；勾选独立、已有数据完整；用户确认通过。
- 相关 Commit / PR / Issue：首轮实现 [`23a7cd3`](https://github.com/YOLIIIIII/starry-list/commit/23a7cd3941a28d0724e254ca7b9bb71c9b8fd5c8)（含使用手册、截图与验证记录）；PR / Issue 未创建。初始基线 `830b88f` 不包含本轮 UX。

### SL-002

**七天日程空状态优化与快速新增收起**

- 类型：UX；来源：用户实际体验、第一轮 UX 请求及本次追加反馈（2026-10-15）。这是同一需求的补充，不另立重复 ID。
- 当前问题：原先七个空日期重复显示「添加一件小事…」。首轮已改为点击加号按需新增，用户认可大部分改进；但空输入框点击外部不会收起，再点加号也不会收起，多个日期可以同时保留输入区，范围/视图切换后的空输入状态需要清理。
- 目标体验：真实任务最醒目，空日期只保留日期、数量和加号；快捷新增出现与消失自然，同时保护已输入但未保存的标题。
- 推荐实现方向：在已有 QuickAdd / startAdding / stopAdding 路径中小范围修复。区分空白草稿与非空草稿，处理输入区域外点击及对应加号，统一管理唯一活动新增区；切换范围/视图时清理失效空输入。不要直接用 blur 清空全部草稿，也不要影响点击提交按钮或中文输入法。
- 优先级：P0；预计工作量：小（追加 UX 修复）；技术风险：中，重点是失焦事件顺序、输入法、异步保存和非空草稿丢失。
- 前置依赖：复用现有本地新增及错误保留流程，无新数据结构要求。需要用户确认：如已有非空草稿又点击其他日期加号，具体提示/保留方式在开发时明确；必须满足不静默丢失和最多一个新增区两项约束。
- 当前状态：In Review；首轮已开发、提交并有自动化/桌面记录；最新源码仍使用可容纳多个日期的 `addingDates`，加号只展开，没有空白外部点击收起处理；补充修复**未开始开发、未验证**。用户认可大部分不表示已完成验收；发布：未发布。
- 验收标准：
  1. 点击日期「+」后展开对应输入框并自动获得焦点。
  2. 输入框为空或只有空白时，点击输入区域之外的位置自动收起；区域内点击或点提交按钮不能误触发取消。
  3. 空输入时，再点对应「+」可以收起。
  4. 按 Esc 可取消快速新增，中文输入法组合期间不误取消。
  5. 输入标题按 Enter，只有持久化成功后收起并显示真实任务；失败保留输入及错误。
  6. 非空未保存内容不会因点击其他地方、其他日期加号或切换操作而被静默丢弃；需保留或明确处理。
  7. 同一时间最多展开一个快速新增输入区域。
  8. 切换日期范围或视图，不留下失效空输入框；返回时不复活已失效的空输入。非空草稿仍遵守第 6 项。
  9. 不影响正常新增、编辑、完成、日期归属、优先级和数据库保存；原有数据完整。
  10. 空日期无重复占位提示，整段为空最多一个整体提示，真实任务层级高于新增提示；用户体验确认后才关闭本需求。
- 相关 Commit / PR / Issue：首轮实现 [`23a7cd3`](https://github.com/YOLIIIIII/starry-list/commit/23a7cd3941a28d0724e254ca7b9bb71c9b8fd5c8)；追加修复没有 Commit；PR / Issue 未创建。不能用首轮或本次复跑的 59 项前端测试、既有 12 组桌面记录代替新增反馈的验证。

### SL-003

**透明窗口视觉体系重设计**

- 类型：Visual；来源：用户实际体验。
- 当前问题：矩形顶栏与外层圆角不协调，阅读层次不足，复杂壁纸穿透干扰内容，专注背景块不统一。
- 目标体验：统一圆角玻璃底板，顶部与主体协调，少量背景层和舒适内边距，透明与不透明状态都清晰。
- 推荐实现方向：先盘点背景 alpha、圆角裁切与衬底，再评审局部视觉方案；不顺带改驻留机制。
- 优先级：P1；预计工作量：中；技术风险：中高，WebView2、GPU、透明窗口裁切与对比度差异。
- 前置依赖：现有透明/不透明回退；与 SL-004 协调视觉层级，但不硬性串行。需要用户确认：复杂背景与实色方案的观感。
- 当前状态：Backlog；尚未开发、测试或验收；未发布。
- 验收标准：顶栏与外层圆角无突兀矩形；明暗、复杂测试背景下标题和任务可读；40%–100% 设置语义不变；文字/输入控件不整体变淡；减少背景层不损害滚动与宽窄布局；不透明回退正常；使用合成测试背景，不公开私人壁纸。
- 相关 Commit / PR / Issue：无实现提交；PR / Issue 未创建。

### SL-004

**默认字号和全局字号设置**

- 类型：Feature；来源：用户实际体验与设计讨论。
- 当前问题：七天日程、计数与辅助文字偏小；新增真实反馈：专注模式「当日清单」快速新增输入文字明显小于已有任务标题。总览和专注复用 QuickAdd，但当前 `.quick-add input` 为 11px，任务标题为 13px，缺乏协调；当前没有用户字号档位。
- 目标体验：快速新增与真实任务的文字大小协调，两种视图统一；任务正文默认建议约 15–16px，按设计系统微调。先建立舒服的文字层级，再提供小 / 标准 / 大档位，放大文字不放大整页布局。占位符可较浅，但不应明显缩小。
- 推荐实现方向：先以 SL-004-A 完成输入与任务标题的局部字号协调；随后评审正文、任务、日期和辅助文字的字体变量，集中管理档位与持久化。避免只放大输入导致和任务标题再次失衡；按现有设置兼容策略评估，不擅改任务结构。
- 优先级：P1；预计工作量：中；技术风险：中，窄屏、DPI、长标题、表单和计数重叠。
- 前置依赖：SL-004-A 不依赖 SL-003 或全局字号设置，可与 SL-002 / SL-019 一轮处理；全局层级与 SL-003 共同评审可读性。需要用户确认：局部文字协调程度、默认层级及三个档位实际观感。
- 当前状态：Backlog；尚未开发、测试或验收；未发布。
- 验收标准：
  1. 两种视图的快速新增输入文字与已有任务标题字号基本一致；默认任务正文以约 15–16px 为设计参考，实际取值需协调现有层级并经体验确认。
  2. 占位符可降低颜色强调，字号与输入文字保持一致，不通过缩小占位符制造层级。
  3. 380px 窄窗口、宽窗口及不同 DPI 下，无水平溢出、按钮裁切、重叠；长输入仍可编辑，Enter / Esc / 中文输入及失败保留行为不变。
  4. 全局范围：默认任务和辅助文字比现状易读；设置提供字号档位并重启保留，各档长标题合理换行/省略且完整内容可访问；窗口尺寸与任务日期不受影响。
  5. SL-004-A 通过仅表示局部字号修复验收，不表示全局设置完成，父需求不能因此直接标 Done。
- 子任务 **SL-004-A：快速新增输入框字号协调**。优先级 P1；工作量小；风险低至中（窄屏/选择器影响）；状态 Backlog。仅涵盖第 1–3 项及相关任务标题的必要协调，不增加全局字号设置，不放大整页；用户确认后单独记录其验收结果。本次只记录，未改 CSS。
- 相关 Commit / PR / Issue：无实现提交；PR / Issue 未创建。

### SL-006

**Windows 桌面驻留模式：先研究，再决定实现**

- 类型：Technical；来源：用户新增的重要产品需求。
- 当前问题：现有普通窗口和始终置顶不足以实现桌面组件体验。**关闭 alwaysOnTop 不等于桌面驻留。**
- 目标体验：提供桌面驻留 / 普通窗口 / 始终置顶三个模式。驻留时普通浏览器、Word、资源管理器自然盖住日历，返回桌面可见；任务仍可点击、编辑、拖动和缩放，不抢焦点、不影响全屏，重启保留设置。
- 推荐实现方向：A. 技术研究与可行性原型；B. 研究报告经用户确认后，才安排正式实现。保留普通窗口与置顶模式作可靠回退；不得未经验证采用 Explorer Hack。
- 优先级：P1；预计工作量：待评估；技术风险：高，窗口层级、Shell 生命周期、焦点、输入、透明渲染及系统更新兼容性。

### SL-019

**单条任务快捷删除入口优化**

- 类型：UX；来源：用户实际体验并确认已有删除能力（2026-10-15）；原反馈误用 SL-010，已按用户确认使用新 ID，主题需求不迁移。
- 当前问题：删除入口不够明显。实际入口是专注模式只读详情 →「编辑」→ 抽屉中部表单向下滚动，在「更多选项」下面的「删除任务」；并非缺失数据库删除功能。总览与专注的真实任务行均无快捷操作菜单。
- 目标体验：两种视图都能方便操作单条真实任务，快速发现编辑与删除；保留抽屉删除和删除后撤销，维持紫黄、简洁风格。
- 推荐实现方向：先复核 `TaskRow`、`TaskEditor`、App 删除确认与 `store.remove` / `store.restore`；建议在任务行右侧增加「···」菜单，提供「编辑任务」「删除任务」。复用同一确认、持久化、撤销和错误路径，不新增重复数据库删除能力。菜单编辑入口沿用既有抽屉，处理日期定位与未保存草稿。
- 优先级：P1；预计工作量：小；技术风险：中，菜单事件冒泡、焦点、窄屏定位、异步删除与撤销、草稿保护回归。
- 前置依赖：现有删除确认、串行持久化与撤销均已存在；不依赖透明视觉或驻留模式。需要用户确认：菜单位置、可发现性及窄窗口实际操作感受；授权开发时再确定细节。
- 当前状态：Backlog；快捷入口尚未开发、测试或验收；原删除能力已存在且有既有测试；未发布。
- 验收标准：
  1. 总览七天日程与专注清单的真实任务行都有可发现的单条操作入口；空日期不显示任务菜单。
  2. 菜单提供「编辑任务」「删除任务」；编辑定位正确日期和任务，沿用抽屉；不误勾选完成或误展开详情，未保存草稿不静默丢失。
  3. 保留抽屉现有「删除任务」，所有入口复用同一确认、删除和撤销逻辑；取消确认不改变数据。
  4. 持久化成功后才移除任务并提示可撤销；失败不伪称成功，保留任务并明确反馈。撤销恢复原任务内容、日期、优先级、分类及完成状态。
  5. 删除和撤销后，月历预览、七天日程、专注清单、任务计数及进度同步，重启读取结果正确。
  6. 菜单支持键盘打开、导航、选择和 Esc 关闭，焦点可返回触发按钮；窄窗口及滚动容器边缘无裁切、遮挡或横向溢出。
  7. 维持紫黄主题和紧凑任务行，正常新增、编辑、完成和 SQLite 数据不受损；通过相关回归并由用户体验确认。
- 相关 Commit / PR / Issue：快捷菜单无实现提交；现有抽屉删除可见于首轮 UX 提交 `23a7cd3`，数据库删除在初始基线已存在；PR / Issue 未创建。
