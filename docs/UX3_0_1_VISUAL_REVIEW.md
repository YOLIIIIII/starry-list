# UX3.0.1 外观模式与通知修正

对应 [SL-003-A / SL-003-B](PRODUCT_BACKLOG.md#sl-003)，是 UX3.0 用户反馈的续修；默认阅读优先，14px、主界面布局、任务编辑及数据库表结构不变。用户本轮没有附入参考图片，以下按文字描述实现，不声称复现了未收到的原图。视觉仍待用户最终确认。

## 三种材质

| 模式             | 材质与阅读保护                                                                                | 100% / 实色回退                |
| ---------------- | --------------------------------------------------------------------------------------------- | ------------------------------ |
| 阅读优先（默认） | UX3.0 的稳定奶油阅读区、轻透明外壳                                                            | 奶油实色，任务行紧凑           |
| 轻玻璃           | 冷浅紫与奶油清透材质，面板透视更多；任务行、日期数字有局部衬底，不请求原生模糊                | 清浅冷紫实色与明亮任务行       |
| 梦幻毛玻璃       | 柔紫浅金材质；受支持的 Windows 请求系统 Acrylic，空隙及面板保留更明显背景氛围；任务行单独保护 | 关闭原生模糊，保留柔紫浅金配色 |

外观模式决定材质；「背景不透明度」仍控制外壳的实际 40%–100%，不是三个模式固定不同透明度。各层保护随滑块单调增强；文本与图标不设整体 opacity。输入、只读长详情、抽屉、菜单、弹窗及通知保持高可读底色。

40% 时，轻玻璃任务行的理论合成背景覆盖约 94.1%；梦幻原生毛玻璃约 93.9%；阅读优先主阅读区约 99.4%。这些数字是多层 alpha 合成，不是文字 opacity 或全界面的统一不透明度。100% 三种模式均不透视，通过配色、描边和任务局部材质继续区分。

## 原生模糊及降级

仅梦幻毛玻璃、透明原生窗口、未开启实色回退且低于 100% 时请求 [Tauri 官方 setEffects / Acrylic](https://v2.tauri.app/reference/javascript/api/namespacewindow/#seteffects)。限定 Windows 11 build 22621+，避开官方提示存在拖动/缩放性能问题的旧系统路径；其他系统、原生不透明包或调用失败使用保护更强的柔紫玻璃底色，设置中明确说明。没有新增 Explorer 嵌入、驻留或未验证窗口 Hack。

系统关闭透明效果、节能、远程桌面和 GPU 条件仍可能影响实际模糊。设置显示「已请求系统 Acrylic」而不是保证每台机器都呈现相同效果；接口成功不等于像素必然模糊。本轮测试同时查询 Windows 的 [DWMWA_SYSTEMBACKDROP_TYPE](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwmwindowattribute)，并观察实际合成截图。其他模式、100% 和实色回退主动清除 Acrylic；异步请求串行，快速切换不会让迟到的旧请求重新启用材质。

未使用 CSS backdrop-filter 来冒充桌面模糊。CSS 方案不能保证过滤 WebView 外的桌面像素；本轮局部背景本身即可保证降级阅读，不依赖滤镜是否支持。

## 通知与验收

短成功文案原先没有弹性宽度，关闭按钮跟在文案旁；现在所有通知文案占剩余宽度，关闭按钮固定最右，撤销在文案与关闭之间。长文案省略，完整任务标题仍可悬停查看。普通恢复/保存提示与撤销提示共用约 5 秒计时和 hover / focus / 弹窗暂停；多条有效撤销继续独立保留，数据库撤销逻辑不变。

1. 设置 → 外观模式，依次选择三种模式，再比较 40%、70%、100%。
2. 在深浅、复杂背景前查看日期、任务及长计划，确认自己偏好的材质与可读性。
3. 打开窄窗口的设置、菜单、抽屉；新增、删除、撤销后确认关闭按钮在右侧，悬停暂停、离开后计时恢复。
4. 重启确认模式保留；实色回退应关闭模糊与透视，保留材质配色。
