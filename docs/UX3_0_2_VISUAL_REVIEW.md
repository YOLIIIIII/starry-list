# UX3.0.2 玻璃留白与材质稳定性

对应 [SL-003-C / SL-003-D](PRODUCT_BACKLOG.md#sl-003)，延续 UX3.0.1 三材质方向。用户已确认通知位置、设置持久化良好；本轮视觉及原环境毛玻璃现象仍待确认，不等于正式发布。

## 视觉原因与调整

| 区域     | UX3.0.1 问题                                                                  | UX3.0.2                                                                                 |
| -------- | ----------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| 星期标题 | 玻璃模式额外铺整条半透明底色；标题列没有日期网格的 4px 缝隙，中心位置略有偏差 | 纯文字、无底条；同样七列与 4px 间隙，每个文字单元居中                                   |
| 月历预览 | 每行任务都有白色小底贴，小格内容易粘连                                        | 玻璃以日期格为保护面；取消任务常驻底贴，5px 预览间距，文字适度加深；hover / focus 保留  |
| 专注清单 | 任务行加上高保护底色，但行与行直接相接                                        | 任务分组之间 7px 缝隙、10px 圆角，展开详情仍属于同一分组；新增区与最后任务至少 9px 分离 |
| 七天日程 | 有底色的任务行连续排列                                                        | 同样增加 7px 行间隔，保留原日期分组、计数、行内修改与菜单                               |

间距与圆角使用玻璃作用域的集中 CSS token；没有降低正文 opacity、整体缩放或引入更多滤镜。三种材质的 alpha 公式保持不变，40% / 70% / 100% 继续真实改变外壳；阅读优先保留稳定衬底，轻玻璃更通透，梦幻保留柔紫浅金和可降级 Acrylic。100% 和原生不透明关闭模糊与透视，通过配色区分。

## 原生残留：证据与限制

用户报告梦幻模式多次总览/专注切换后底色变实，这是有效 Bug 反馈。本机旧版普通窗口在三档透明度各切换 30 轮，未出现累积；每五轮采样，单外壳、单主区、无额外弹层，DWM 和背景颜色稳定。不能据此否定用户现象，也不能认定已复现相同触发方式。

另在隔离的旧版原生窗口中注入「Acrylic 已应用，但调用回报失败」，成功复现 **前端 fallback + DWM Acrylic=3 同时存在**。原实现只提高 CSS 保护，没有清理可能部分完成的原生效果。它是确认存在的故障路径，未证明是用户机器的唯一根因。

新版保持一个窗口级材质队列：已成功的相同请求不重加，尚未执行/能力查询中的过期请求跳过；替换前清理，应用失败后清理再进入 CSS 降级。总览与专注不各自申请材质、不随导航重复叠 Acrylic，没有新增 overlay 或通过不断重置原生效果掩盖问题。无法完成系统清理的极端故障仍不能保证桌面渲染；可改阅读优先/实色回退并反馈环境信息。

原生故障注入只在测试进程中拦截一次 IPC 响应，数据库和生产代码无测试开关。通过 Windows DWM 属性与真实合成采样验证，不只看 Promise；最终结果与未验证边界见 [验证记录](VALIDATION.md)。

## 复现与体验

实现提交 [`5bbdb88`](https://github.com/YOLIIIIII/starry-list/commit/5bbdb88a99b2a7f1010ee9c1c83c1bc917791cd5)。更多本轮样例：[阅读总览](screenshots/ux302/reading-colorful-70-overview.png)、[轻玻璃窄通知](screenshots/ux302/glass-notification-380.png)、[梦幻窄抽屉](screenshots/ux302/frosted-drawer-380.png)。截图类型与验证范围见验证记录。

按验证记录构建独立调试标识（不要用正式数据库），执行：

```powershell
npm run test:appearance -- --stability-only
npm run test:appearance
```

第一条连续切换、设置/透明度切换及部分应用失败清理；第二条三材质、三透明度、四合成背景及前景/宽窄/原生拖动检查。`--fault-only` 可单独运行设置及故障注入，旧版应暴露残留而新版应清除；`--matrix-only` 仅合成矩阵；`--foreground-only --viewport-only` 只检查 WebView 几何，不代表桌面材质。测试助手只将自己的合成背景移到隔离窗口正后方，仍保留全部隐私拒绝检查，不关闭用户应用。

1. 设置选轻玻璃/梦幻、40%，检查星期标题居中、月历任务不粘连。
2. 专注模式安排多项任务，查看 7px 缝隙、只读详情和新增区是否舒适，缩到窄窗口复查按钮。
3. 梦幻模式总览/专注来回切换至少 30 轮，再改 70% / 100%，开关设置、切换三材质，确认没有多出来的实色底层。
4. 重启检查偏好，继续测试 Enter 连续新增、失焦保存、行内修改、完成、删除/撤销和抽屉草稿。若出现原异常，请记录系统版本、档位与步骤；无需分享私人桌面截图。
