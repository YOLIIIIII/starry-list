维护者：yoli。以下日期为本次整理确认日期（2026-10-15，Asia/Shanghai）；既有原则来自原始产品需求与实现，不虚构早期单独决策日期。讨论中的实现建议不等于最终技术选择。重新评估时追加记录并关联旧 ID，不静默改写历史。

### DEC-001

**本地优先，当前不接云端。**

- 日期：2026-10-15；状态：已确认的当前产品边界。
- 原因：无需账号、离线可用和隐私是核心价值，减少服务依赖。
- 影响范围：SQLite、备份、设置和日常工作流程；不得默认上传数据。
- 是否重新评估：SL-015 / SL-016 获准立项时可重新评估可选能力，但保留离线核心，须明确用户同意与隐私边界。

- 日期：2026-10-15；状态：已确认的当前平台策略。
- 原因：集中验证 Windows 10/11 桌面体验，避免未测试的跨平台承诺。
- 影响范围：构建、兼容性矩阵、发布顺序；平台接口保持适当抽象。
- 是否重新评估：SL-014 有真实设备、维护资源及明确用户需求后评估，不承诺日期。

### DEC-003

- 日期：2026-10-15；状态：已确认的品牌基线。

- 影响范围：月历、日程、编辑器、空状态及视觉优化。

### DEC-004

**统筹总览与专注编辑为默认双视图。**

### DEC-005

**分类非强制，每条任务最多一个分类。**

- 日期：2026-10-15；状态：已确认的低认知负担原则。
- 原因：用户只输入标题即可添加，避免为了组织信息而增加操作。
- 影响范围：快速新增、编辑、分类管理及筛选。

### DEC-006

**长任务采用完整标题、可选简称、详情分层。**

- 日期：2026-10-15；状态：已确认的数据表达原则。
- 原因：短任务紧凑、月历摘要清楚、长计划有空间；不以截取固定汉字修改原标题。

- 是否重新评估：可评审更好的编辑器，但须证明必要性并保护已有文本、换行和备份兼容。

### DEC-011

**透明外壳与稳定阅读衬底分层，透明度不作用于整棵 DOM。**

- 日期：2026-10-19；状态：SL-003 当前实现方案，视觉仍待用户验收，可继续调整具体配色与数值。
- 原因：旧补色公式在中间透明度保护更弱，且不同区域分别叠色产生突兀矩形；复杂壁纸和背后文字不能抢占任务可读性。
- 影响范围：surfaceAlphas、连续顶栏、月历/七天/专注与前景背景。外壳保持 40%–100% 真实变化；内容局部保护单调增强；不依赖 backdrop-filter、全局 opacity 或新增原生特效。应用 ID、数据及 14px 不变；不提前实施 SL-004 / SL-005 / SL-006。
- 是否重新评估：用户安装 UX3.0 后根据视觉舒适度与兼容性反馈复核；硬件范围、DPI、原生不透明和性能结论以实际验证为准，不泛称所有设备已认证。

### DEC-012

**阅读优先为默认，材质偏好与透明度独立；原生毛玻璃可降级。**

- 日期：2026-10-20；状态：UX3.0.1 当前实现方向，视觉待用户验收，补充 DEC-011。
- 原因：用户认可阅读保护，但希望可选更通透或更梦幻的材质。保持一个清晰默认值，同时让玻璃偏好不牺牲关键文本；CSS 滤镜不能冒充桌面模糊。
- 影响范围：SL-003-A / B、surfaces、设置 JSON、Tauri 官方效果权限与通知样式/计时。只新增可默认的设置字段，不改数据库表、迁移或任务；旧数据默认阅读。Acrylic 仅现代 Windows 透明窗口请求，不透明/旧系统/失败有明确降级，100% 清除原生效果。
- 是否重新评估：三种模式的强度、系统兼容性和观感由体验包反馈复核；不把一次 Windows 11 验证推广到所有硬件，不提前开发 SL-004 / SL-005 / SL-006。

### DEC-013

**毛玻璃使用单窗口原生背景合成，不伪装窗口激活状态。**

- 日期：2026-10-22；状态：UX3.0.3 实现方案，待 SL-003-E 用户验收，补充 DEC-012。
- 原因：官方系统背景 Acrylic 设计为失焦时转实色，本机旧版真实复现明显底色改变；反复重设效果或伪造焦点无法可靠修复这一策略。
- 影响范围：仅支持的 Windows 11 透明窗口请求 Windows.UI.Composition HostBackdropBrush 与 DesktopWindowTarget，材质及柔色保持一个窗口级实例、UI 线程持有并成对清理。复用已缓存 Windows Rust 绑定，不引入 Windows App SDK 运行时、Explorer Hack 或任务/数据库改动。Windows 10、原生不透明、100%、透明效果禁用/高对比、原生失败按既有规则降级；系统电源/GPU/远程会话策略仍可能限制模糊，不能强制绕过。
- 是否重新评估：其他 GPU、Windows 更新、节能和远程桌面需继续验证；本机正常电源下激活/失焦稳定不等于全设备保证。保留阅读优先与实色回退；用户确认视觉与兼容性后再关闭需求。

### DEC-014

**字号按阅读角色分档，顶部保留两行，只收紧冗余留白。**

- 日期：2026-10-23；状态：UX3.1 当前实现，SL-004 / SL-005 待用户安装验收。
- 原因：UX3.0.4 已获得三种外观的正面反馈；任务 14px 是稳定基准，同时需要适配不同阅读偏好、给内容更多空间。
- 影响范围：独立 `text_size` 设置为 small / standard / large；任务、快速输入和长计划使用 13 / 14 / 16px，UI、辅助、标题、密集月历各有集中 token。三种材质不覆盖字体或间距；不用 zoom、整页 transform 或父级 opacity。旧 JSON 缺字段默认 standard，读取不写回；沿用设置 JSON 和备份版本 1，不改表、迁移、任务、应用标识或正式版本号。选择立即预览，保存中明确提示，失败回滚并显示真实错误。
- 顶部：保留星球、中文品牌、两视图和窗口控制；宽屏保留英文识别与文案，窄屏隐藏英文，矮屏隐藏装饰句。标题区/模式行收紧外部 padding，窗口按钮统一 30×30px，模式按钮最小 34px 高。仅独立空白区域用于拖窗，Logo/模式/窗口按钮不作 drag region；圆角与材质实现沿用 UX3.0.4。通知依实际模式按钮边界避让，跟随字号重新测量。
- 是否重新评估：三档长任务、窄/矮窗口、独立滚动与真实桌面操作经本轮验证后仍待用户确认；SL-006 及其他规划没有因此获得开发授权。具体数值、实测高度与验证边界见 [UX3.1 对比](UX3_1_VISUAL_REVIEW.md) 和 [验证记录](VALIDATION.md)。

### DEC-015

**顶部由阅读偏好选择；专注新增与任务滚动分离。**

- 日期：2026-10-26；状态：UX3.2 用户明确授权的当前方案，待安装体验；替代 DEC-014 中「仅收紧两行顶部」部分，字号角色及数据兼容决策保留。
- 原因：用户认可 UX3.1 字号，但反馈压缩顶部美观下降，长详情会把新增框挤出视口。默认恢复舒展与辨识度，同时允许有需要时节省空间。
- 影响：`header_layout` 独立设置 classic / compact，旧配置默认 classic，双语品牌保留；紧凑只隐藏视觉导航文字，保留 aria-label、title、aria-pressed。设置与字号一样即时预览/持久化/失败回滚，不影响原生材质队列。仅空白拖窗，窗口/模式按钮命中不缩小。
- 专注：列表为唯一正文滚动容器，完整详情随列表阅读，底部新增区作为面板的独立 flex 子项，不遮盖正文，不复制 QuickAdd 或改变 Enter/失焦/草稿保存状态机。抽屉继续独立滚动与固定保存栏；短窗只调日期导航留白。
- 数据：复用设置 JSON、备份版本 1、现有串行写入；Zod / Serde 默认值及白名单两端一致，读取不改写旧 JSON。不改任务 Schema、迁移、应用标识或正式版本号。
- 复核：两顶部 × 三字号 × 三材质与短/窄窗口、真实 Windows 交互及用户体验分别登记；其他功能未授权开发。见 [UX3.2 对比](UX3_2_VISUAL_REVIEW.md)。

### DEC-016

**SL-006-A 保留 Tauri bottom 作为低成本研究候选，当前不选定正式驻留实现。**

- 日期：2026-10-26；状态：研究结论，待用户确认；延续 DEC-007 的 A/B 门槛，不授权 B。
- 证据：锁定 Tauri 2.12.3 / Tao 0.37.1 的内置机制不仅单次置底，还有消息级排序；独立 Win11 原型激活后仍靠后。但 Win+D 实际最小化，未达到返回桌面可见；Win32 单次置底激活后上浮。可点击性、IME、Shell 生命周期及兼容矩阵仍有缺口。
- 当前判断：报告选 **C：暂不推荐实现** 当前完整目标；SL-006 保持 Research，不偷换成“普通窗口靠后”，不集成正式主窗口。
- 风险边界：WorkerW / Progman 只作高风险候选，当前用户桌面不发送内部消息、不重挂父窗、不重启 Explorer。公开 SetParent API 不意味着依赖的 Explorer 拓扑受支持。
- 再评估：在可恢复的隔离系统补齐 Win+D、原生输入与恢复、Explorer 生命周期及约定设备矩阵，由用户确认报告/限制后再决定 SL-006-B。见 [完整研究](research/SL-006-WINDOWS-DESKTOP-RESIDENCY.md)。

2026-10-28 续记：用户已确认结论 C，暂停 SL-006-B 正式实现；SL-006 保持 Research，不删除、不标 Done。本轮只开发 SL-007，不修改或集成研究原型。

### DEC-017

**日程范围锚定选中日期，切换复用现有草稿保存机制。**

- 日期：2026-10-28；状态：用户明确授权的 SL-007 实现规则，待安装验收。
- 规则：rolling 默认从选中日开始连续七天；week 为包含该日的周一至周日，包括过去/未来日期。前后导航均对选中日增减 7 天，保留星期位置；回到今天不改变范围偏好。
- 界面：原日程标题改为原生可访问选择框，日期范围显示完整年份；用有用的范围信息替换装饰句，保留新增/导航位置，避免额外工具栏。
- 数据：新增设置 JSON 字段 agenda_range，前端 Zod / Rust Serde 缺省 rolling，两端白名单一致；保留备份版本 1，无任务表/迁移变化。选择立即预览，保存失败恢复旧范围，成功后才视为持久化。
- 保存：范围切换只走现有 guard / QuickAdd.save / store 队列，非空草稿先保存原日期，失败不切换；IME 组合不导航、共享保存 Promise 防重复、失焦与撤销逻辑保留。任务保存与范围设置保存分开报告结果，不因后者失败删除已保存任务。
- 边界：仅 SL-007；SL-006 正式实现暂停，动画、拖动、每日星星与成长页面不开发。原生测试、模拟输入、用户验收和正式发布分别记录。
